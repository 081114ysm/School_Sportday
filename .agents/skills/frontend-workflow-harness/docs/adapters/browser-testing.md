# 브라우저·테스트 어댑터

지원 브라우저와 버전, viewport, 실제 기기 필요 여부는 제품 환경을 기준으로 정한다. 기본 예시 폭은 320/768/1280px이며 충분한 전체 기기 목록을 뜻하지 않는다.

| 검사 계층 | 사용할 때 |
|---|---|
| 단위 | 입력 검증·변환·정렬 같은 순수 로직의 경계 |
| 컴포넌트 통합 | 사용자 입력과 오류·로딩·성공 전환, 요청 계약 |
| E2E | route·인증·실제 화면을 잇는 중요한 사용자 여정 |
| 시각 회귀 | 고정 환경에서 기존 화면·상태의 레이아웃 변화 |
| 접근성 자동 + 수동 | semantic 오류 탐지와 키보드·초점·읽기 흐름 확인 |

기존 도구와 테스트 수준을 먼저 활용한다. 구현과 똑같은 계산을 복제하거나 snapshot만 갱신하는 테스트는 피한다. 버그 수정에서는 재현했던 조건을 검증하고, fixture나 selector가 실제 사용자 동작과 동떨어지지 않게 한다.

성능 예산은 기존 측정 기준을 재사용한다. 측정 환경·데이터·throttling·build mode를 고정해 이전 값과 비교한다. LCP/INP/CLS 같은 지표도 측정하지 않았으면 추정 수치를 쓰지 않는다. Lighthouse 점수 하나로 전체 성능을 판정하지 않는다.

개발 서버 기동 성공과 화면 검증은 별개다. 실제 URL에서 동작·console·network·overflow를 확인하고 증거 파일을 남긴다. 결과 구조는 [브라우저 QA](../rules/verification.md)를 따른다.

# 코드 리뷰

리뷰는 diff와 계약의 논리·회귀 위험을 찾는다. 브라우저 QA는 실제 사용자 동작을 확인한다. 결과를 섞지 않는다.

## 실제로 수행한 방법을 적기

`reviewMode: self`는 구현자가 자체 점검한 결과다. `independent`는 별도의 사람·허용된 도구가 구현 대화와 추론을 받지 않고 점검한 결과다. 사용할 수 없는 code-review 스킬이나 서브에이전트를 가정하지 않는다. 프로젝트 또는 사용자 지시가 독립 리뷰를 요구하면 도구 없이 완료했다고 표시하지 않는다.

독립 리뷰에는 승인된 기획서, merge-base 기준 diff, 파일과 필요한 호출부·테스트만 전달한다. 저장소 내용만으로 재현할 수 있는 지적을 받는다. 현재 작업의 평가를 좋게 유도하는 설명은 전달하지 않는다.

## 확인할 내용

- 범위·계약·기존 컨벤션과 어긋난 변경.
- 버그, 요청 경합·취소·중복 쓰기·인증 만료·cache 누출.
- 성능·불필요한 렌더·무제한 데이터·bundle 영향.
- 가독성·네이밍·중복·계층 책임·유지보수성과 확장성.
- 보안·권한·XSS·공개 환경변수·실제 운영 실패와 복구.
- 접근성·반응형·SSR·hydration·회귀 테스트의 빠진 경로.

지적에는 재현 조건, 실제 영향, `file:line`, 수정안을 쓴다. 선택지가 실제로 중요한 경우 장단점을 비교한다. 뻔한 오타에 대안 두 개를 억지로 만들지 않는다. 근거가 부족하면 가설과 확인 방법을 적는다.

| 심각도 | 기준 | 처리 |
|---|---|---|
| critical | 데이터 유실·인증 우회·심각한 노출 | 수정 전 통과 불가 |
| high | 핵심 여정 실패·중복 결제 등 | 수정 전 통과 불가 |
| medium | 제한된 상황의 기능·유지보수 문제 | 수정 또는 근거를 기록한 수용 |
| low | 작은 개선 | 수정 또는 근거를 기록한 수용 |

기능 `evidence/review.json`에 실제 method/reviewer/scope/findings를 작성한다. 결함이 없으면 빈 findings와 확인한 범위를 남긴다. 생성된 예시는 high/open으로 시작하므로 리뷰 전에는 통과하지 않는다.

```sh
node scripts/harness.mjs record --kind review --file .frontend-workflow/features/42-auth-login/evidence/review.json
```

수정 후 이전 리뷰의 해시는 무효다. 실제 최종 diff를 재검토하고 보고서를 갱신한다. JSON 기록이 독립성을 인증하지는 않는다. 결과를 작성하는 사람·에이전트가 사실을 지킬 책임이 있다.

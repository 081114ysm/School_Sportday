# 브라우저 QA와 완료 증거

빌드 성공, HTTP 200, 스크린샷 한 장으로 사용자 흐름을 검증했다고 하지 않는다. 실제 화면에서 인수 조건의 행동과 결과를 확인한다. 실제로 실행하지 못한 것은 fail 또는 blocked로 남긴다. CLI는 해당 상태를 통과로 받아들이지 않는다.

## 자동 검사

`run all`은 설정의 명령을 순서대로 실행하고 첫 실패에서 멈춘다. 종료 코드·시간·명령·코드 지문을 저장한다. shell을 사용하지 않으므로 `&&`, 파이프, 환경변수 대입은 argv에 쓰지 않는다. 필요하면 프로젝트에서 검토한 wrapper script를 별도로 실행한다.

실행 후 코드가 바뀌면 이전 결과를 무효로 한다. 자동 수정하는 lint/format이 파일을 바꿨다면 그 실행은 통과로 기록하지 않는다. 수정 내용을 확인한 뒤 다시 실행한다. 빌드 산출물·캐시·로그는 프로젝트 `.gitignore`로 제외한다.

## 브라우저에서 확인할 여섯 영역

| JSON key | 반드시 확인할 결과 |
|---|---|
| journey | AC ID별 실제 클릭·입력·navigation과 데이터 결과 |
| states | 적용되는 로딩·정상·빈 상태·입력/서버 오류·권한·처리 중·성공과 복구 |
| responsive | 설정한 뷰포트 전체, 긴 콘텐츠, 작은 화면 overflow, 200% 확대 |
| keyboard | Tab/Shift+Tab/Enter/Space/Escape, focus 유지·이동·복귀, IME |
| console | 새 오류·경고, hydration, 기존 오류와의 구분 |
| network | 실제 method/path/status, 중복·취소·응답 역전·재시도, 민감정보 노출 |

journey/responsive/keyboard는 해당 없음으로 처리하지 않는다. 나머지 영역이 없는 경우 `na`와 구체적인 이유를 남긴다. 예를 들어 정적 문구 변경에서는 network가 해당 없을 수 있다. 이 체크리스트는 전체 WCAG 인증을 대신하지 않는다.

브라우저·버전, 검증 URL, viewport, API 모드, 실제 결과를 `evidence/browser.json`에 쓴다. 스크린샷·trace·검사 결과를 같은 evidence 디렉터리에 저장하고 artifacts에 상대 경로를 넣는다. 파일 내용도 해시로 확인하므로 나중에 증거가 바뀌면 재기록해야 한다.

## 기능별 QA.md 자동 저장

`start`가 `.frontend-workflow/features/{id}/QA.md`를 만든다. `run`, `record`, `advance`, `replan` 등 상태를 저장하는 명령은 같은 문서를 자동 갱신한다. 미실행 검사와 시작 시 복사한 JSON 예시는 통과 결과로 사용하지 않는다.

문서는 자동 검사, 브라우저 여섯 영역, 검증 환경과 API 모드, 증거 링크, 리뷰·후속 검증과 미검증 항목을 요약한다. QA 완료 조건은 현재 기획 승인·필수 검사·리뷰·브라우저 증거로 계산하며 PR의 CI·머지와 구분한다. Mock 검증은 실제 API 연동 검증의 한계도 표시한다.

브라우저 보고서가 fail/blocked이거나 형식·뷰포트·필수 증거 조건을 충족하지 못하면 `record --kind browser`는 실패 종료한다. 빈 파일이나 읽을 수 없는 파일도 거부 사유를 남긴다. 읽을 수 없는 보고서는 증거 링크를 만들지 않는다. 거부 사유와 읽은 보고 내용은 `QA.md`에 남기고 기존 브라우저 통과 기록을 제거하므로, 이전 성공을 재사용할 수 없다. 실제 재검증 후 유효한 보고서를 다시 기록해야 한다.

`QA.md`의 자동 마커 사이만 갱신한다. 수동 메모는 마커 밖에 쓴다. 마커가 깨졌거나 중복되면 자동 덮어쓰기를 거부한다. 상태 저장 뒤 문서 갱신이 실패한 경우에는 상태가 이미 저장됐다는 오류를 출력하므로, 원문을 보존해 원인을 해결한 뒤 `qa-report`로 복구한다.

```sh
node scripts/harness.mjs qa-report
```

이 명령은 기록을 현재 코드·기획·설정·증거와 대조해 문서만 재생성한다. 저장된 증거를 바꾸거나 검사를 다시 실행하지 않는다. 외부 코드 수정 직후의 문서는 이전 스냅샷일 수 있으므로 **에이전트가 QA 결과를 사용자에게 보여주기 직전에 실행한다.** `status`는 읽기 전용이다. Markdown 편집만으로 승인이나 검증을 통과할 수 없다.

Playwright가 이미 있다면 role/label 기반 선택자와 사용자 결과 assertion을 우선한다. 임의 sleep보다 관찰 가능한 상태를 기다린다. 테스트를 위해 앱 코드를 복제하지 않는다. 시각 회귀 baseline은 OS·브라우저·폰트·viewport를 고정하고 실제로 검토한다. 자동 승인으로 차이를 덮지 않는다.

## Mock과 실제 API

Mock은 계약에 기반한 정상·지연·빈 결과·400/401/403/409/429/500·timeout 케이스를 재현하는 데 쓴다. 실제 API를 붙였을 때 확인해야 할 CORS·쿠키·인증 만료·응답 schema·페이지네이션을 대체하지 못한다.

`apiMode: mock` 결과는 화면 검증으로만 보고한다. 프로젝트의 `requireLiveApi: true`이면 live 증거 전에는 ready가 될 수 없다. 실제 서버가 없으면 이유와 필요한 환경을 남기고 해당 단계에서 전달한다. 백엔드 API를 임의로 추가·변경하지 않는다.

## 남길 증거와 한계

- 자동 검사 JSON은 실행 결과다. 첫 변경 명령에서 만드는 `.frontend-workflow/.gitignore`가 원시 로그와 lock을 제외한다. 앱 루트의 기존 ignore는 변경하지 않는다. 공유할 로그·화면은 민감정보를 제거한다.
- 리뷰 JSON과 브라우저 JSON은 사람이 사실대로 작성하는 보고서다. 해시는 변경만 감지하며 결과의 진실성·충분성을 인증하지 않는다.
- `QA.md`는 이 기록에서 만든 읽기용 문서다. 자동 생성 자체가 실제 브라우저 검증을 뜻하지 않는다. 원시 출력은 포함하지 않으며 보고서·화면의 민감정보는 기록 전에 확인한다.
- CLI가 코드 전체를 감시하지 않는다. Git이 추적하거나 ignore하지 않은 파일만 지문화한다. 지문 밖 설정·외부 API·환경변수가 바뀌면 직접 재검증한다.
- 증거가 부족하면 최종 보고에 구현 완료 / 검증 완료 / 미검증을 구분한다. 무조건 '완벽하다'고 보고하지 않는다.
